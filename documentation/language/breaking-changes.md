# Valkyrie 破坏性变更管理

## 定义

破坏性变更是指导致现有合法 Valkyrie 代码无法编译或行为发生改变的变更，包括但不限于：

- 移除语言特性
- 改变语法规则
- 改变类型检查行为
- 移除或重命名标准库函数
- 改变函数签名
- 改变默认行为

## 变更级别

### 级别 1：兼容变更（无需迁移）

- 新增语言特性
- 新增标准库函数
- 放宽类型检查规则
- 新增诊断警告

### 级别 2：轻微破坏（需要迁移指南）

- 新增编译错误（之前合法的代码现在报错）
- 重命名标准库函数
- 改变函数参数顺序

### 级别 3：重大破坏（需要长期过渡）

- 移除语言特性
- 改变核心语义
- 移除标准库模块

## 过渡策略

### 级别 2 变更流程

1. **版本 N**：引入变更，同时保留旧行为并标记为 `[Deprecated]`
2. **版本 N+1**：旧行为产生编译警告
3. **版本 N+2**：移除旧行为

### 级别 3 变更流程

1. **版本 N**：发布公告，说明变更计划和迁移路径
2. **版本 N+1**：引入 `[Deprecated]`，旧行为仍可用
3. **版本 N+2**：旧行为产生编译警告
4. **版本 N+3**：移除旧行为

## 迁移工具

编译器提供以下迁移辅助：

- `valkyrie check --deprecated`：列出所有使用已弃用 API 的位置
- `valkyrie fix`：自动修复可机械迁移的变更
- 诊断消息中包含迁移建议

## 版本语义

Valkyrie 遵循语义化版本：

- **主版本号**：包含级别 3 破坏性变更
- **次版本号**：包含级别 2 破坏性变更或新特性
- **修订号**：仅包含兼容性修复

## 变更日志

所有破坏性变更必须记录在 `CHANGELOG.md` 中，格式：

```
### 破坏性变更

- **VALK-BC-001**: 移除 `old_func()`，使用 `new_func()` 替代
  - 影响范围：使用 `old_func()` 的代码
  - 迁移方式：全局替换 `old_func` → `new_func`
  - 废弃版本：0.x.0
  - 移除版本：0.(x+2).0
```
